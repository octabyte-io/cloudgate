# A cloud Delete that cannot finish keeps its row, unlike a Server's

Status: accepted, extending the Environment Delete rule. Built for a cloud Service's Delete, and for an Environment's, with its Environment network's removal.

On a Server, a Delete always drops the Service's row and names in its response whatever it could not remove ([ADR-0018](0018-a-delete-reclaims-each-artifact-on-the-machine-that-made-it.md)). What it leaves is a directory or a Docker artifact on a machine the operator already pays for. In a Cloud account, the same leftover is a security group, a load balancer or a network card in someone else's account, and it may still be billing. The row and its **Infrastructure state** are the only things that still know about it. So **a Delete of a Service or an Environment in a Cloud account that leaves anything behind keeps the row, marked "Delete incomplete"**. It names each leftover (type, the cloud's id, region, Cloudgate's mark) and offers only **Retry**, which destroys again from the kept state, or **Forget**, which drops the row. Both need the same statement as the Delete.

The alternative was to keep ADR-0018's shape on every target: drop the row and report the leftovers once. We rejected it because a report read once and then lost becomes a cost no screen shows, which is the "spend in someone else's account" constraint. A future change should not "unify" the two back.

Consequences, all deliberate:

- **A cloud Delete is a Cloud run that only destroys**, recorded as a Deployment, so the operator can watch it and its log survives a failure. It uses the same queue, the same lock and the same "no Cancel once applying" rule as a deploy. When the Environment network is removed with no Service left, that run is a Deployment of the **Environment network**, a Deployment parent of its own.
- **A Delete's report has two lists.** *Kept* holds what a rule keeps on purpose: a bucket with files or a final snapshot. Each is named once with its cost, then forgotten, and none of them makes the Delete incomplete. *Left* holds what should have gone but did not, found by a mark search and, for what a mark search cannot find, by id: the task role the state holds, and the network cards AWS made on the state's security groups. Only *Left* keeps the row. In slice 3 *Kept* was always empty; a bucket on AWS that holds files is the first thing in it, kept with nothing in AWS touched and its row and state gone at once, while one whose emptying stopped partway is *Left*, "partly emptied".
- **Forget writes the list into the audit log**, not into a Deployment log, because the Deployments go with the row. This replaces the Environment rule's "records the same list in the Deployment log".
- **A Delete-incomplete Service cannot be deployed or started.** Its state still describes what is left, and a deploy would mix new resources into a half-destroyed state.
- **A cloud Delete that cannot reach its Cloud account fails before removing anything**, and a run cut off part-way (by the time limit or a restart) ends incomplete, never clean.
- **An Environment's Delete deletes its cloud Services first, each through its own Delete, and removes the Environment network only once none is left**; the Environment, and each row and state still holding something, stay until all of it is gone. Retry and Forget there need `environment: ['delete']`.
- **A postgres on RDS and a redis on ElastiCache are deleted the same way, and keep a final snapshot**. The run is a Deployment of the database. RDS's deletion protection is lifted first by a direct call on the cloud port, so a run that fails after it says the protection is now off. The run then applies, to the instance or replication group alone, the two settings `tofu destroy` reads from the state: protection off, and the final snapshot `<project>-<environment>-<service>-final-<date>`, dated the day the Delete was asked. The snapshot carries Cloudgate's tags and is the report's one *Kept* entry, named with its region, size and monthly cost. Nothing of it is stored after the report. "Also delete its data (no final snapshot)" is offered only on that database's own Delete and on its Plan destroy row, and needs only `service: ['delete']`. An Environment's Delete refuses the flag and keeps every database's snapshot.
- **A plan's destroy of a cloud Service is this Delete**, and a plan's removal of an Environment network is the same destroy-only run as the Environment's Delete, confirmed by typing the network's name.
