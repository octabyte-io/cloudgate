# The MCP endpoint is in-process, stateless, and answers inside the proxy's deadline

The MCP server is a route group **inside the Nest process** (ADR-0003, reaffirmed). It is reached at `<console origin>/mcp` through one Next rewrite beside `/backend/*` and `/api/auth/*`, and built on `@modelcontextprotocol/server` 2.x. **Amended: the rewrite is not the whole of the console's part.** The console's sign-in gate (`frontend/src/proxy.ts`) runs before rewrites and sends every cookieless request to `/sign-in`, so its matcher excludes exactly `/mcp` as well. It has to be in-process: tool handlers call service methods with a `PermissionCtx` (ADR-0023), and the dispatcher writes audit rows in-process. Another process could do neither without a second audit path and a hole in the refusal of Agent keys on REST. Cloudgate also installs natively, so a separate server would have been its first container.

**The rules, each of which a future change would otherwise be tempted to "fix":**

- **No Traefik entry, and no installer change.** ADR-0013's `dynamic/cloudgate.yml` is untouched. A router there exists only once a console domain is assigned, which would leave a bare `http://host:3000` install with no endpoint. The documented address is always "your console's address + `/mcp`". Forward auth is never in front of it.
- **Any request carrying an `Origin` header is refused with 403.** MCP clients send none, and a browser has no business calling this endpoint with a bearer key. better-auth skips `Origin` validation when there is no cookie, so the endpoint does the check itself. Refusing any `Origin` needs no allow-list, can't drift from the trusted-origins lists, and closes DNS rebinding completely.
- **Every tool finishes under a server-side deadline of about 30s, well below the console's 240s idle `proxyTimeout`.** Nothing waits on Swarm convergence. Database start/stop scale with `--detach` and are polled like deploys. A deadline that is hit returns the `failed` outcome and writes an audit row, never a cut socket. A test pins deadline < `proxyTimeout`, so raising one without the other goes red. **Amended: Applications scale with `--detach` too, and a Compose cannot.** `start_service`/`stop_service` pass `detach` to the Application's and the database's `start`/`stop`, which only the tool path sets, so the console's buttons still wait for convergence as they did. A Compose's start and stop are `docker compose start`/`stop` and `docker stack rm`, none of which has a detached form, so they run to completion as the console's do; a stack slower than the deadline answers `failed` with its row while the command finishes on its own. That is the one place a tool can still meet the deadline in normal use, and it does not reopen this ADR: the answer is still a result, never a cut socket.
- **Every response is `application/json`, never SSE**, and there is no GET stream. **Amended, on how the SDK is wired to keep this:** `createMcpHandler`'s own 2025-era fallback (its default `legacy: 'stateless'`) answers `text/event-stream` whatever `responseMode` says, so the handler runs with `legacy: 'reject'` and `responseMode: 'json'` for the 2026-07-28 leg, and a request `isLegacyRequest` classifies as 2025-era goes to a per-request `WebStandardStreamableHTTPServerTransport` with `enableJsonResponse: true` — the SDK's documented pattern for serving the legacy leg yourself. That leg keeps the 2025 transport's rule that a POST must `Accept` both `application/json` and `text/event-stream` (406 otherwise), although it never answers with the second. Revision `2026-07-28` specifies a cut stream as a cancellation, so a stream that ended because a lease expired and one that ended because the network dropped would look the same to an agent. With no stream there is nothing to cut. **Not reopened by the Gateway (ADR-0040).** The Gateway streams and has no 30 s deadline, but it is its own route with its own Traefik router, not `/mcp` and not the Next rewrite, so nothing here applies to it.
- **Dual-era, with no state in either era.** The endpoint serves the current revision plus every earlier Streamable HTTP revision that a client we document still speaks only (at launch `2026-07-28`, `2025-11-25`, `2025-06-18`, `2025-03-26`). It refuses `2024-11-05` and the HTTP+SSE transport. It never mints an `Mcp-Session-Id` and answers GET/DELETE with 405, so there is **no session affinity**. This is a permanent rule, not a launch list: dropping a revision is a decision with a release note, never a silent SDK bump, and the SDK's own defaults (which accept `2024-11-05`) are overridden by our list. **Amended: overriding the list is not enough to refuse `2024-11-05`.** Given our list, the SDK still *negotiates* an `initialize` asking for it up to `2025-11-25`, which is the spec's behaviour for an unknown revision. So the dispatcher refuses any 2025-era revision older than `2025-03-26` itself, on `initialize` and in the `MCP-Protocol-Version` header, with HTTP 400 and JSON-RPC `-32602` naming the served list, and writes the `refused`/`unsupported-revision` row. The 2026-07-28 leg's `-32022` is the SDK's own answer; the dispatcher only writes its row. `tools/list` advertises `listChanged: false` rather than omitting it — the SDK sets the capability on the first `registerTool` and false is the closest it allows — and its `cacheScope`/`ttlMs` hints exist only on the 2026-07-28 leg, since a 2025-era result has no field for them.
- **No enablement switch.** After an upgrade the endpoint exists and answers 401 until an Agent key exists. A switch would guard nothing that a missing Agent doesn't already guard.
- **No OAuth discovery is served**, so no client starts a flow Cloudgate cannot finish. An Agent authenticates with an Agent key as `Authorization: Bearer`, at this endpoint and nowhere else.

**What reopens this ADR:** a tool that cannot finish inside the deadline. It reopens the deadline rule and the JSON-only rule together, because the only way to be long-running and conformant is a stream, and a stream brings back cancellation-on-cut and the proxy's idle timeout.

**Pinned by** `frontend/server/mcp-deadline.test.mjs` (`TOOL_DEADLINE_MS` < `proxyTimeout`, and the one rewrite), `frontend/src/proxy.test.ts` (the gate lets exactly `/mcp` through), and `backend/test/mcp/mcp-endpoint.e2e-spec.ts` (each served revision, `2024-11-05` refused, `-32022` on the 2026 leg, GET/DELETE 405, no `Mcp-Session-Id`, no `text/event-stream`, the `Origin` refusal), with the deadline itself in `mcp-dispatcher-stages.e2e-spec.ts`.
