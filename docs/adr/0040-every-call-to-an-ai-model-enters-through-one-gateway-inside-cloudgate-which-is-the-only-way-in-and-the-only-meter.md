# Every call to an AI model enters through one gateway inside Cloudgate, which is the only way in and the only meter

Status: accepted.

An AI model is reached only through the **Gateway**: a proxy inside the backend process (ADR-0003), on a fixed path of its own on the platform host, `/ai`, served by its own Traefik routers (`cloudgate-router-gateway`, beside the console's in `dynamic/cloudgate.yml`) rather than the console's Next rewrite. Its endpoint is `<platform host URL>/ai/<AI model's Application id>/v1`. It forwards only `POST /v1/chat/completions`, `POST /v1/completions`, `POST /v1/embeddings` and `GET /v1/models`, holds each call to the one model its AI model serves, and writes one usage row per call when the call settles. The rows hold tokens marked reported or estimated, and never prompt or response bodies. It reaches each AI model **through that machine's Traefik**, on a gateway-only router (`dynamic/ai-gateway+<appName>.yml`, written owner-only at each deploy) that matches the AI model's path prefix **and** a per-AI-model upstream secret in `X-Cloudgate-Upstream`, strips both, and sends the call to the runtime by name on `cloudgate-ai`. The secret is encrypted at rest and never read back (ADR-0019). This hop exists because the backend is a host process that reaches Servers only over SSH. An AI model has no Domain and no published port, and it sits on a dedicated `cloudgate-ai` overlay, never `cloudgate-network`, that no other Service may join. Inference runtimes have no auth covering their whole API, so a route around the gateway is a model that is both unmetered and open to anyone.

**Amended: the router file sits at the top of `dynamic/`, not in `dynamic/ai-gateway/`.** It was `dynamic/ai-gateway/<appName>.yml`, and a live walk found a new AI model unreachable (`502 model_not_answering`, Traefik's own 404) until an unrelated top-level file changed. `traefik:v3.6.7`'s file provider reads subdirectories at each reload but watches only `dynamic/` itself, so a file written below it raises no reload — the measurement `compose+<appName>` was already named for. `+` is outside `APP_NAME_REGEX`, so no Application's file can take the name. The file is `0600` but `dynamic/` stays open, so it is renamed into place from a file created `0600` (`replaceOwnerOnlyFile*`). A deploy removes an earlier version's `ai-gateway/<appName>.yml` (and the directory once empty) before it writes, and a Delete removes both.

**Considered options.**

- **LiteLLM run as a Service.** Rejected, because its keys and spend would live outside the one check and outside ADR-0019, at a 4 GiB floor plus its own Postgres.
- **A Cloudgate-built gateway per Server.** Rejected for now, as a new distributed part to version and to feed keys to. It may come later as an optimisation behind the same URL.
- **A sidecar per AI model.** Rejected.
- **The gateway inside `/mcp`.** Rejected, because a stream is exactly what ADR-0025 says reopens `/mcp`'s rules.
- **A Domain, or "internal only", per AI model.** Rejected. The gateway is on no overlay, so "internal" has no honest meaning, and a Domain is a way in that skips the meter.

**Consequences.**

- **Authorization is the one check's fourth entry point (ADR-0023, amended).** Only Agent keys are accepted, authenticated by the same `McpAuthenticator` as at `/mcp`, and Personal keys are refused. A call needs `service: ['call']` on the AI model's Application (`checkServiceAccess(ctx, applicationId, 'call')`), held by the `agentCaller` role and by nothing else an Agent can hold. Suspension and `agent_expires_at` are honoured as at `/mcp`. A revoked key refuses new calls.
- **Refusals are OpenAI-shaped and say as little as they can.** An unknown, revoked, expired, suspended or personal key is one 401 "Key refused". A deleted AI model, a plain Application, another Organization's, one outside the grant, and a key without `call` are one 404 "AI model not found or not permitted", so a key can't map which models exist. A path outside the allowlist (`/api/*` included) is 404, a `model` other than the one served is 400 and never rewritten (the one served as the facet spells it or as the runtime's own listing does: a live walk found Ollama's `GET /v1/models` naming a facet's `all-minilm` as `all-minilm:latest`, and the gateway refusing that id back), an AI model that isn't running is 503, and a body over 16 MiB is 413 (the Gateway reads its own bodies, past the 100 kB every other route takes). No refused call reaches the runtime.
- **Spend belongs to the AI model, not the caller.** An `ai_usage` row counts toward the AI model's own Project and Environment and records the calling Agent, because an Agent's grant is a set, with no single Environment to charge. When Project B calls Project A's model, the spend is A's. A call refused before authentication writes no row. One refused after it writes a `refused` row with zero tokens, except where there is no AI model in the Agent's Organization to hang it on. Rows outlive a removed Agent, keeping its name, and are deleted with the AI model, its Environment and its Project. Raw rows are kept 90 days, and daily rollups for the model's life (slice 3).
- **A call writes no audit row.** The route is `@Public()`, so `AuditInterceptor` has no actor, and it is named in `NOT_RECORDED_ROUTES` because its first segment, `ai`, would otherwise read as an `aiProvider` change.
- **The gateway shares `/ai` with Cloudgate's own AI provider's REST routes** (`AiController`). Those are the console's under its `/backend` rewrite, so on the public host `/ai/` is the gateway's whole. Inside the backend the gateway's route needs a segment after the id; the only `AiController` route with one, `POST /ai/:id/test-connection`, is registered first and keeps it.
- **An AI model is an Application.** It is not a new Service kind and not a new Deployment parent (ADR-0017 untouched). Its runtime is fixed at create, from a closed list, and the fields the gateway depends on are locked.
- **Its weights are a cache, and a Delete always reclaims them.** One platform-owned `<appName>-weights` volume per AI model, never shared and never backed up, pruned to one model after a successful swap. This extends ADR-0018's list.
- **Accepted costs.** A caller on Server X calling a model on X goes through the platform host and back. The hop from the platform host to a Server's Traefik is plain HTTP on its `web` entry point, guarded by the secret alone. A backend restart cuts calls that are running. With no console domain assigned, the endpoint is the console's own address and the console's Next rewrite forwards `/ai/*` to the backend, so a stream there is cut after 240 s of silence (`proxyTimeout`); a console domain gives it its own routers and no such cut. An install that assigned its console domain before the gateway existed gets the routers at the next boot.

**What would falsify this.** Models hosted elsewhere (OpenAI, Anthropic), which need per-vendor accounting. A per-Server gateway that keeps its own keys. A caller that must reach a runtime directly for a protocol the gateway can't forward.

**The tripwire that fires first** is a write that puts an AI model on another network, or gives it a Domain or a published port. The locked network fields and the refusal of `cloudgate-ai` to any other Service make that a test edit, not a quiet change.

**Pinned by** `backend/test/gateway/gateway.e2e-spec.ts` (the allowlist and model hold, the refused-before and refused-after row rules, the 401 and 404 refusals, the upstream secret on the hop and the gateway-only router written at deploy and removed by a Delete, rows outliving the Agent and going with the AI model, its Environment and its Project, no audit row), `backend/test/traefik/web-server.spec.ts` (the gateway's own routers on the console host), the `agentCaller` role pin in `backend/test/rbac/agent-roles.e2e-spec.ts`, and `route-permissions.baseline.ts` and `audit-log-kinds.spec.ts` (the route's census entries). Streaming is pinned by `backend/test/gateway/gateway-streaming.e2e-spec.ts`: events handed on as the runtime produces them, `stream_options.include_usage` forced and the usage chunk kept from a caller who didn't ask, tokens flagged estimated when the usage never arrives (counted with `gpt-tokenizer`'s `cl100k_base`, an estimate for any model, which is all the flag claims), a caller's hang-up abandoning the runtime's request with a `client-aborted` row, a runtime breaking off with a `runtime-error` row, and a revoke letting a running stream finish with its row. The upstream-secret hop through a real Traefik is the slice's live walk.
